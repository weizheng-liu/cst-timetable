# 判断の記録 (DECISIONS)

依頼時に「不明点は自分で判断して記録し、止まらずに進める」と指示されたため、判断とその理由をここに残す。

| # | 判断 | 理由 |
|---|---|---|
| 1 | リポジトリ名は `cst-timetable`、Public | GitHub Pages を無料で使うには Public が必要。依頼者に作成してもらった。 |
| 2 | **HTML ではなくシラバスサイトの公開 JSON API を取得する** | サイトは Next.js のクライアントレンダリングで HTML にデータがない。画面自身が使っている公開 API（ログイン不要）を使う方が正確で壊れにくく、リクエスト数も少ない。詳細は `SYLLABUS_SITE.md`。 |
| 3 | テストの fixture は HTML ではなく実際の API レスポンス (JSON) | 2 と同じ理由。`--dump-fixtures` で Actions から本物のレスポンスを保存した。 |
| 4 | 爬虫は Python 標準ライブラリのみ | 依存を増やさず、Actions でも手元でもそのまま動く。 |
| 5 | 取得は GitHub Actions 上で実行 | 開発環境のネットワークからは大学サイトに届かなかったが、Actions からは届くことを確認した。定期更新も同じ仕組みで動く。 |
| 6 | 定期実行は 4/1 と 9/15（いずれも 03:00 JST） | 「4月初、9月中」の指示どおり。新年度シラバスは 3/30 頃に公開されるため 4/1 なら揃っている。 |
| 7 | 年度の既定値は「4月以降はその年、1〜3月は前年」 | 3 月時点では新年度シラバスが未公開の可能性があるため。 |
| 8 | 科目の一意キーは **時間割CD**（例 J51A）。同じ科目名でもクラス・曜日違いは別科目として扱う | 時間割CD は年度内で一意。クラス1/2・再履修クラスを区別できる。 |
| 9 | 1 つの時間割CD に複数のシラバスページがある場合（卒業研究など）、教員名を統合して 1 件にする | 研究室ごとにページがあるが、時間割としては 1 コマ。 |
| 10 | 連続コマ（水1・2 など）の授業計画は 1 回 1 件にまとめる | API は 1 回分をコマ数ぶんの行で返すため、そのままだと .ics が重複する。 |

| 12 | 前期 / 後期 を切り替えて表示し、年間科目は両方に出す | 1 枚の表に両学期を重ねると重複判定も見た目も破綻する。 |
| 13 | 学年フィルタ: 既定は自分の学年の科目だけ、「他学年も表示」で全学年 | 再履修や上級生科目の先取りもあるため完全には隠さない。 |
| 14 | 必修/選択はシラバスに項目がないため、**学部要覧の授業科目配置表から判定**（名前で照合） | シラバス API には必修区分がない。要覧の灰色セル＝必修を PDF の図形情報から読み取る。 |
| 15 | 科目名照合は NFKC 正規化＋空白除去（Ⅰ→I など） | 要覧とシラバスで「Ⅰ」と「I」が混在しているため。 |
| 16 | 卒業要件は `data/requirements/{入学年度}_{学科スラッグ}.json`。常に `verified: false` で出力し、画面に「未確認」を表示 | 指示どおり。人が確認したら手で `true` にする。再抽出しても `REQUIREMENTS_REVIEW.md` と JSON が再生成される。 |
| 17 | 要覧 PDF は抽出に必要な 2 ページだけを fixture としてリポジトリに置く | PDF 全体 (14MB) は不要で、テストの再現に必要な最小限にした。 |
| 18 | 卒業要件の集計は「今年度に選んだ科目 + 自分で入力した修得済み単位（区分ごと）」 | 過去の成績はどこからも取得しない（個人情報を扱わない方針）。必要な人だけ手入力でき、端末内にのみ保存。 |
| 19 | 配置表にない科目（共通科目配置表の教養科目など）は「区分を判定できなかった科目」として合計にだけ加える | 誤った区分に入れるより安全。 |
| 20 | 同じ科目を 2 クラス選んだ場合、単位は 1 回だけ数える | 同一科目の重複修得は単位にならないため。 |

| 23 | 授業日が掲載されていない科目は .ics に含めず、件数を通知 | 推測で日付を作ると誤情報になる。 |

| 26 | 端末間の移行は JSON エクスポート/インポート。インポート時は既知のフィールドだけ受け付ける | 壊れた/悪意あるファイルで状態が壊れないように。 |
